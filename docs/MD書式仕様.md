# Mindra — MD 書式仕様（マインドマップ）

Mindra が図として扱う MD の書き方です。人間にも AI にも、普通の Markdown として読めることを優先します。

## 対象の書式

図になるのは、次の 2 つだけです。

- 見出し: `#` から `######` まで
- 箇条書き: `-` で始まる行（入れ子は 2 スペースのインデント）

それ以外（段落、コードブロック、表、引用、リンクなど）は、MVP では図に出しません。

## ノードの階層

見出しの深さと箇条書きのインデントを、ひとつの階層として扱います。

```markdown
# 旅行

## 持ち物
- パスポート
- 充電器
  - 変換プラグ

## 予定
- 1 日目
```

上の MD は次の木になります。

```
旅行
├─ 持ち物
│  ├─ パスポート
│  └─ 充電器
│     └─ 変換プラグ
└─ 予定
   └─ 1 日目
```

### 規則

1. 見出しの親は、その上にある直近の見出しのうち、自分より浅い（`#` の数が少ない）ものにする。
   - 例: `# 旅行` の下の `## 持ち物` は、旅行の子。
2. 見出しの下の箇条書き（インデント 0）は、その直前の見出しの子にする。
   - 例: `## 持ち物` の下の `- パスポート` は、持ち物の子。
3. 箇条書きの親は、その上にある直近の箇条書きのうち、自分より浅い（インデントが少ない）ものにする。見つからなければ、直前の見出しにする。
   - 例: `- 充電器` の下の `  - 変換プラグ` は、充電器の子。
4. 見出しの階層が飛んでも（`#` の下に `###` が来ても）、規則 1 のとおり、浅い直近の見出しの子にする。

## ルートノード

- 最初の `#` 見出しを、ルートノード（中心）にする。
- `#` 見出しが無ければ、ファイル名（拡張子を除く）をルートにする。
- 2 つ目以降の `#` 見出しは、ルートの子として扱う。
- ルートより前に現れた見出し、または浅い親が見つからない見出しは、ルートの子として扱う。

## 対象外の行の扱い

- 見出しと箇条書き以外の行は、無視する（ノードにしない）。
- 空行は、階層を切らない。
- コードブロック（```）の中の `#` や `-` は、図にしない。コードブロックの中は読み飛ばす。

## front matter

- 先頭の `---` で囲まれた部分は front matter とする。
- `view: mindmap` と書けばマインドマップとして表示する。
- front matter が無い、または `view` が無ければ、マインドマップとして表示する。
- `view` に未知の値が書かれていたら、マインドマップとして表示し、画面に注意を出す。
- front matter の中身は、図の描画には使わない（MVP）。

```markdown
---
view: mindmap
---

# 旅行
```

## 見出しと箇条書きの文字

- 見出しと箇条書きの文字は、行頭の記号（`#`、`-`）を除いた部分をノードの文字にする。
- 前後の空白は取り除く。
- 文字の中の Markdown 記法（`**太字**`、`` `コード` ``、`[リンク](url)`）は、記号を取り除いてプレーンな文字として表示する。

## 例（完全版）

```markdown
---
view: mindmap
---

# Mindra の計画

## 目的
- AI と人間が同じ MD を共有する
  - AI は読み書きする
  - 人間は図で見る

## MVP
- MD を図として表示する
- 変更を自動で反映する

このような段落は図に出ない。

## 今は作らない
- フローチャート
- 往復編集
```

## コメント

- ノードの直下に続く引用（`> ` で始まる行）は、そのノードのコメントになる。木の要素（ノード）にはしない。
- 箇条書きのコメントは、箇条書きより 2 スペース深く書く。見出しのコメントは、インデントなしで書く。
- 空行で引用が切れたら、そこから先はコメントにならない。
- 図では、コメントをノードの下に引用のように表示する。

```markdown
- Charger
  > Needs a travel adapter
  - Adapter
```

## 色

- 項目の色は、行末に `{color:#rrggbb}` と書く。例: `- Charger {color:#fff1a8}`
- 色は画面には文字として出ない。名前を変えても、色は残る。
- 色の指定は、名前（木の要素）には数えない。
- 画面から選べるのは、7 色のパステル（赤、オレンジ、黄、緑、青、紫、グレー）。MD に手で書くときは、任意の `#rrggbb` を使える。
- 線の色とテーマ（明るい / 暗い）は、その画面の設定として保存する（ブラウザに保存し、MD には書かない）。

```markdown
- Charger {color:#fff1a8}
  > Needs a travel adapter
  - Adapter
```

## 図から追加するときの書式

図の上で追加すると、次の書式の行が増えます。

| 操作 | 追加される行 |
| :--- | :--- |
| 見出しの子 | 1 段深い見出し（`##` の子は `###`）。その見出しの子孫の後ろに入る |
| 箇条書きの子 | 2 つ深い箇条書き（インデント + 2 スペース） |
| ルート（最初の `#`）の子 | `##` の見出し |
| ファイル名のルートの子 | 末尾に `##` の見出し |

### 親を追加する

選んだノードの上に、新しい親を足します。選んだノードとその子孫（コメントも含む）は、新しい親の下へ移ります。

| 対象 | 追加される親 | 移った後の書式 |
| :--- | :--- | :--- |
| 箇条書き | 同じインデントの箇条書き | 元のブロックは 2 スペース下がる |
| 見出し | 同じ深さの見出し | 元のブロックの見出しは、すべて 1 段下がる |
| ルート | 不可 | ルートには親を足せない |

- 6 段目の見出しを含むブロックは、1 段下げられないので、親を足せない。

- 6 段目の見出しの子は、箇条書きで足す。
- ファイル名のルートは、名前を変えられない。

## 将来の拡張（予約のみ）

- `view` の値として、フローチャートなどほかの図の種類を追加する予定。
- 値の追加の規則は、図の種類を足すときに、この文書へ追記する。
