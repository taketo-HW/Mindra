# Mindra — 最初の指示

あなたはこのリポジトリ「Mindra」の管理者です。監督は T（人間）です。
応答は日本語。選択肢は `1a` `1b` `2a` の形（番号＋英小文字）で示してください。

## 何を作るか

AI と人間をつなぐ Web アプリ。

- **正本は Markdown（.md）だけ。** 図のデータはすべて .md ファイルとして保存する。
- **人間は MD を見ない。** ブラウザでファイルを開くと、MD がマインドマップやフローチャートとして表示される。
- **AI は MD を読み書きする。** 人間は図を見て直感で使い、AI は同じものを MD として扱う。1 つのファイルを人間と AI が別の見え方で共有する。
- 最初はマインドマップ。その後フローチャートなど、いろいろな図を表示できるようにして、多用途で楽しめるものにする。

## 原則

1. **MD が唯一の正本。** 図は MD から毎回作る「見え方」にすぎず、図だけの独自データを持たない。
2. **MD は人間が読んでも自然に見えること。** 見出しや箇条書きなど、普通の Markdown を基本にする。
3. **図の種類は差し替えられること。** 「MD → 図」の描画部（renderer）を種類ごとに足せる薄い I/F にする。図の種類は front matter（例: `view: mindmap`）かファイルの構造で決める。
4. **作る → 進化させる。** 動く最小を先に作る。重い機能は作らず、拡張の余地だけ残す。
5. **ドキュメントファースト。** 方針・MD の書式仕様・図ごとの対応規則を、実装の前に `docs/` に書く。

## 最初のゴール（MVP）

- ブラウザでローカルの .md ファイル（またはフォルダ）を指定すると、マインドマップとして表示する。
  - 見出しと箇条書きの階層を、ノードの階層にする。
- ファイルが変わったら、表示も自動で更新する（AI が MD を書き換えると図が変わる）。
- 単体テストで「MD → 図のデータ構造」の変換を確かめる。

4. 技術の候補を 2〜3 案、選択式で提案する。決めるのは T。
