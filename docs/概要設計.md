# Mindra — 概要設計

## 目的

AI と人間が、同じ Markdown ファイルを別の見え方で共有する。

- 人間は、ブラウザで MD を開き、マインドマップとして直感的に見る。
- AI は、同じ MD をそのまま読み書きする。

## 原則

1. **MD が唯一の正本。** 図は MD から毎回作る見え方にすぎない。
2. **MD は人間が読んでも自然に見えること。** 見出しや箇条書きなど普通の Markdown を基本にする。
3. **図の種類は差し替えられること。** 「MD → 図」の描画部を種類ごとに足せる薄いインターフェースにする。
4. **作る → 進化させる。** 動く最小を先に作る。
5. **ドキュメントファースト。** 仕様は実装の前に `docs/` に書く。

## 全体構成

サーバーなしで動く静的アプリです。

```
index.html        … 画面の骨格（読み込みボタンと描画領域）
src/
  parse.js        … MD → 中間データ（木構造）。描画に依存しない純粋関数
  render.js       … 中間データ → 図（DOM / SVG）。図の種類ごとに差し替える
  watch.js        … File System Access API でファイルを読み、更新を検知する
  app.js          … 上の部品をつなぐ
styles.css
tests/            … node --test による単体テスト
```

- 依存ライブラリはなし。ビルドもなし。`index.html` をブラウザで開けば動く（`file://` でも可）。
- ファイルの読み込みは、ユーザーが「ファイルを開く」を押して行う。ブラウザが許可を取り、ページはそのファイルを読む。
- 更新検知は、一定間隔（1 秒ごと）でファイルの内容を読み直す。前回と変わっていたら図を描き直す。

## データの流れ

```
MD ファイル  →  parse（MD → 木）  →  render（木 → 図）  →  画面
     ↑                                                    │
     └──── AI が書き換える ──── 1 秒ごとに検知して描き直す ───┘
```

## 対応ブラウザ

- Chrome / Edge など Chromium 系。File System Access API が必要。
- Firefox / Safari では、ファイル選択は使えず、自動反映もできない。このことは画面に説明を出す。

## MVP の範囲

- 1 ファイルを開いて、マインドマップとして表示する。根を左に置き、枝を右へ伸ばす。親と子は曲線の線で結ぶ。
- 新規作成: 図の種類（今はマインドマップ。フローチャートは準備中）を選び、保存先を決めて、空のファイルを作る。
- 見出しと箇条書きの階層を、ノードの階層にする（規則は `docs/MD書式仕様.md`）。
- ファイルが変わったら、図を自動で描き直す。
- 図の上での操作: 選ぶ、折りたたむ、拡大縮小、子の追加（右側の「＋」、または、どのボタンにもフォーカスがないときの Tab）、一番上の題目の追加（Add topic。ファイルの末尾に untitled を作る。中心とは別の題目）、名前の変更（Enter、またはダブルクリック）。
- AI チャット: 画面の右側のパネル（幅は画面の 1/5、高さは全体）。Claude / Codex / Ollama を選んで話しかける。AI への接続は、補助プログラム（`npm run bridge`、127.0.0.1 のみ）経由。地図の内容も一緒に送る。補助プログラムを止めると、「接続できない」と表示する。
- 色: 項目の色は、7 色のパステルから選ぶ（MD には `{color:#rrggbb}` と書く）。7 色の色そのものは、設定の「Item colors」で変えられる。
- 設定（画面の見た目。MD には書かず、ブラウザに保存する）: テーマ（System / Light（既定）/ Dark / Black / Pink / Blue / Green）、フォント（System / Mincho / Rounded / Monospace）、線・文字・コメントの色。「Settings」のパネルで変え（開いたままマップを操作できる）、項目の色もこのパネルから選ぶ（項目を選んでから色をクリック）。「Reset to default」で既定に戻す。
- 新しい図の保存: AI チャットの答えの図は「Save as new map」で、作業フォルダ（`mindmap` を打った場所）に新しい `.md` として保存し、新しいタブで開く。作業フォルダが分からないとき（ファイル選択で開いたとき）は、フォルダを選んでもらって保存する。同じ名前のファイルは上書きしない。
- Orca での表示: Orca の中で `mindmap <パス>` を実行すると、Orca のブラウザのタブに、編集できる画面が開く（`orca tab create`）。チャットの中に出すときは `mindmap --orca <パス>`（`tools/export-html.mjs`）で、表示専用の 1 枚の HTML を作り、Orca のチャットの中に出す。描画はアプリと同じ部品を埋め込んで使う。外部への通信はしない。折りたたみと、Fit / 100% の切り替えだけができる。
- 開き方: ブラウザでファイル選択（Open MD file）、または `mindmap` コマンド。`mindmap` だけなら新規作成の画面、`mindmap <パス>` なら、そのファイルを図で開く。パスは絶対パスでも相対パス（打ったフォルダ基準）でもよい。`.md` だけを扱う。補助プログラム（`tools/ai-bridge.mjs`）が、ページの配信と読み書きをする。
- 操作の有効・無効: 起動直後は「Settings」「New」「Open MD file」だけが使える。ファイルを開くと、それ以外（子の追加、一番上の題目の追加、名前の変更、拡大縮小、項目の色）が使える。
- コメント: ノードごとに付けられる（右側の「＊」のメニュー）。MD では、ノードの直下の引用（`> `）として保存する。追加と名前の変更は MD に書き戻す（下の「書き戻し」を参照）。
- MD を直接編集した内容も、従来どおり図に反映する。
- MD → 木 の変換を、単体テストで確かめる。

## 今は作らないもの

- フォルダの指定と、複数ファイルのリンク・ナビゲーション
- フローチャートなど、ほかの図の種類（Mermaid の記法を使うかどうかも含めて検討）
- ノードの削除と移動（次の段階）
- ノードのドラッグ（位置は保存しない）
- Firefox / Safari への対応

## 書き戻し

- 図の上の操作は、MD の 1 行の変更に変えてファイルへ保存する。
- 変えるのは対象の行だけ。ほかの行、front matter、BOM、改行コードは残す。
- 保存の前に、画面の表示時と同じ行かを確かめる。ファイルが外で変わっていたら書かずに失敗させ、もう一度操作してもらう。
- 名前を変えるときは、表示していない記号（`**` など）を、変えた行から消す。名前を変えないときは書かない。

## 未決事項

- フローチャートなど、次の図の種類の書式（Mermaid の記法を使うか）。
- 図の見た目（色、フォント、ノードの配置の方式）。MVP では最小限のスタイルにする。
